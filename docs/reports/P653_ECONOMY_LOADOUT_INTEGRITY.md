## Remaining verification and boundaries

No selected finding is left unimplemented. Full VSTest/live-loopback execution and the live 30v30 remain for the socket-enabled follow-up described in the brief. MCP's actual initial `SendBuyLoadout(..., fLaunch:true, ...)` calls and `tools/allegiance-mcp/BotManager.Lifecycle.cs:72` docked-pod relaunch path were inspected; their server-side packet/state behavior is covered by the initial-seat and docked-pod launch regressions. No live bot run is claimed here.

The port retains a non-null hull record on boarded ships, while their refundable hull value is consumed and purchases are blocked. This implements native's single-sale economics without changing the port's non-null hull/status model. Existing child turret changes and docked reparenting remain permitted. Refunds and autonomous credits stop at the int32 wallet limit; purchases that would overflow the wallet are refused before mutation.

Unrelated audit findings and the existing construction travel simplification remain outside this task. No commit, push, deployment or external application write was performed.
