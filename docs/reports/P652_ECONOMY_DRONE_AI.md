## P652b — restore uncontested mining and stable enemy lockout

The original P652 readiness gate incorrectly made NPC identity, miner pilot type, an explicit `MiningAsteroidTarget`, and a non-null side prerequisites for **all** ore accrual. The established player/fixture path mines by proximity and does not create that NPC plan. Native arbitration (`Igc/shipIGC.cpp:2092-2203`) selects among ready contenders; it does not justify removing this port's uncontested player path. Before editing, the unchanged `AsteroidCombatTests.Damaged_but_alive_asteroid_still_mines_normally` and both P477 rate/capacity tests reproduced the reported failures: baseline 0 instead of approximately 75, identity rate 0 instead of approximately 50, and capacity 0 instead of 150. Seven new player/sideless/mixed-contender regression rows also failed before the fix.

`src/Allegiance.Core/Sim/Ship.cs:6929` now checks physical readiness against a supplied rock. NPC miners retain their pilot and active-plan requirements and native strict distance/speed bounds (`shipIGC.cpp:1950-1967`). Player ships retain geometric eligibility without requiring an NPC claim or side, including the previous inclusive distance boundary. Sideless ships use the existing identity attribute accessors. `src/Allegiance.Core/Model/Sector.cs:3882` resolves an NPC's ordered target or a player's first eligible rock, then sends **both** through the same arbitration. Least-ore selection, insertion-order ties, ally handling, and enemy lockout remain in force; only NPC losers receive autonomous unload/land plans. Accrual, capacity, depletion/reporting, and refinery payout formulas are unchanged.

A second regression was reproduced using the failing live contention fixture's stock hull and station placement. Station avoidance accelerated the stopped enemy contender; by tick 7 its velocity exceeded the readiness limit and the friendly miner collected ore. `src/Allegiance.Core/Sim/Ship.cs:5133` now gives an arrived NPC miner's stopped hold precedence over travel avoidance. Native mining controls likewise precede generic movement (`shipIGC.cpp:2249-2263`); the port extends its arrival hold to all ready contenders to keep arbitration stable with its simplified steering. Retreat, displacement, full cargo, and other active travel plans fail readiness and still use normal navigation. The matching regression verifies every tick of a 6,000-tick window with zero accrual and intact mine orders.

The P652 edits that converted older player mining fixtures into NPC fixtures were reversed in `MiningTests`, `MiningSellTests`, `MiningStateWireTests`, and `ShipAsteroidCollisionTests`. Their original player scenarios now exercise the restored production behavior. This supersedes the earlier report paragraph describing those conversions.

## P652c — restore constructor build arrival

Both reported builder failures were reproduced without sockets using the production build-order helper and stock core/map geometry. The new `P652ConstructorBuildTests` initially produced **1 passed, 2 failed** (`/tmp/p652c-before.log`): the ordinary constructor approached successfully, while the reserved constructor and bucket-spawned constructor never registered a building effect. Neither failure came from mining arbitration or the constructor's damage threshold.

The bucket failure was a missing collision exemption. P652 moved constructor travel from `MiningAsteroidTarget` into `BuilderAsteroidTarget`, but `Sector.ResolveShipAsteroidCollision` still exempted only the mining target. The production home-station spawn, dock and auto-launch path could hit the commanded rock before stopped arrival. The impact removed the fixture's zero-HP rock; the ship then stopped nearby with its build target still set, but `TryStartBuilderBuild` rejected it because the rock was no longer in the sector. `/tmp/p652c-diagnostic.log` records that state, including `contained=False`, full constructor health and no retreat. The earlier P652b stock-constructor test did not exercise the real collision caches and home-station launch geometry.

The client-order failure had a separate blocker: its constructor uses `IsBuilding = true` as an idle reservation before sending the build command. Previously the order immediately registered construction; P652's delayed arrival path instead rejected every attempt while that flag remained set. A flag without a registered effect must not prevent a freshly accepted build trip.

Production fixes:

- `Sector.ResolveShipAsteroidCollision` exempts the constructor's accepted build rock during approach and the matching registered effect's rock during construction. The existing mining exemptions remain. Other asteroids retain normal collision handling. This follows the native drilling-builder exclusion (`Igc/shipIGC.cpp:872-884`) and keeps the port's existing target approach exemption consistent with its new constructor target slot.
- `Ship.SetBuilderBuild` clears an unused `IsBuilding` reservation when accepting the trip. A registered construction effect is preserved on repeated orders, preventing duplicate effects or a second pending build target. Arrival still requires the same-sector rock, stopped motion and the existing proximity bounds (`shipIGC.cpp:2810-2827`); construction still uses `StartBuildingEffect`.
- Updated the build-order documentation in `Server.ShipCommands.cs` to describe constructor travel and arrival. P652c leaves mining arbitration, refinery payout and damage-retreat rules unchanged. Neither reported live test was edited.

Four new socket-free regression rows in `tests/Allegiance.Core.Tests/P652ConstructorBuildTests.cs` cover:

- Stock constructors approaching a matching rock from 300 units away, with and without the reserved building flag; both complete construction into a real station and consume the drone/rock. Repeating the order during construction preserves the single effect.
- An already-arrived constructor starting construction on a matching He3 rock while enemy miners remain locked out, with zero constructor mining accrual.
- The first station bucket's real constructor creation, ten-second home-station wait, actual host dock latch and server auto-launch, then an accepted build order at a matching rock 400 units away. Stock CVH collision and station landing caches are attached. The test invokes the production helpers without booting a transport.
